# 搜索与阅读体验重构提案

日期：2026-10-21。调研基线：`b7b19a8`，开始时工作区干净。本交付是设计提案与独立原型，不是业务功能实现。原型名称「片知」为候选，全部内容为自编示例。

## 设计结论

把「历史」和「搜索笔记」统一为 **资料库**。无关键词时浏览已保存的视频笔记；输入关键词时，在同一界面查标题、UP 主、BV 号、标签、笔记和字幕。保留可直达、可分享的搜索 URL，但不再给「搜索笔记」独立的一级导航。

任务代表一次处理过程，笔记代表可反复阅读的内容。两者需要明确区分：资料库面向查找和阅读；任务页面向进度、失败恢复和处理记录。已完成任务直接提供「阅读笔记」，无需先经过任务详情再下钻。

本次采用一套完整方向，做多个可点击页面和响应式状态，避免用几套彼此无关的配色稿替代信息架构判断。蓝灰色是原型表现选择，不是解决割裂的前提；现有樱红色也可以保留为品牌色。

证据路径相对于项目根目录，均为调研时当前代码。浏览器实看了首页、历史和正文搜索的外壳；本地后端未运行，因此历史是连接失败态，未把它描述成真实有数据页面的视觉验收。任务、完成页及 UP 页的现状判断来自源码。

## 页面与流转

```text
资料库（默认入口）
├─ 浏览最近保存的笔记
├─ 搜索 → 视频分组结果 → 笔记命中段落 / 字幕命中时间
│                         └─ 返回：保留查询、范围、排序、滚动与焦点
├─ UP 主已保存内容（资料库内筛选）
│   └─ 显式切换「在线投稿」→ 沿用在线投稿浏览和新建任务能力
└─ 新建笔记 → 任务进度 → 阅读笔记
任务 → 进行中 / 失败 / 处理记录 → 阅读笔记或处理失败
```

建议路由为 `/library?q=…&scope=all&sort=relevance&author=…`、`/documents/:id?tab=notes&revision=…&chunk=…`、`/new`、`/tasks`、`/jobs/:id`。这些是拟议接口与路由，不是已存在能力。旧 `/history`、`/knowledge` 应兼容重定向到对应资料库状态；原有 `/jobs/:id` 外链仍能查看任务。

一级导航保持「资料库 / 新建笔记 / 任务」。桌面用安静的侧栏，手机用三个等宽底部入口。任务入口只有进行中数量或需要处理时才强调，不做信息仪表盘。

### 搜索交互

- 一个框，说明文字「搜索标题、UP 主、BV 号、标签、笔记或字幕」。手机短 placeholder 配可见辅助说明，不把唯一范围说明塞进被截断的 placeholder。
- 默认全范围。用户点击范围选项时沿用查询，后端执行相应范围检索，不能仅过滤已经截断的 12 条结果。
- 统一用 Enter／搜索按钮提交；范围和筛选变更立即更新结果。输入不因请求在途而禁用；新请求取消或忽略旧响应。IME 组合输入不触发误提交。
- 空输入显示近期内容；有查询默认相关性排序，无查询默认最近保存。视频信息精确 BV 命中优先；后续排序实现需要固定规则和稳定的次级排序，不直接混加不同 FTS 表的原始分数。
- 视频分组显示标题、UP、保存时间，以及「标题命中」「笔记 · 章节」「字幕 · 08:24」等来源。没有正文命中的元信息结果也能进入阅读。
- 每组默认 1–2 段，每段约 2–3 行，关键词高亮；更多命中在组内展开，不把整个视频正文铺在搜索列表。
- 「查看笔记」进入对应章节；「定位字幕」进入包含前后文的字幕行；时间戳用于「在 B 站播放」，明确区分站内阅读和站外打开。
- 显示「已展示 X 个视频 / Y 处命中」，只有接口提供完整统计时才显示全库总数。相关性标签不伪装成可信度百分比。
- 筛选区显示生效条件，可逐项移除或清空。UP 主按稳定 mid 过滤，标签按独立字段过滤，避免把作者名拼成关键词代替筛选。

### 阅读与返回

正文标题和来源是页面主体，阅读区之外才是任务信息。笔记／字幕用同层标签切换，不产生额外页面层级。来源搜索条显示关键词、当前位置和「返回搜索结果」。目录桌面靠右，手机折叠。

命中定位以 document + revision + chunk 或时间范围为准；不能只用文本 indexOf，也不能只用章节标题，重复标题和重新生成会使它们失效。找不到旧版本命中时明确提示「内容已更新」，提供当前版本阅读入口，不静默定位到错误段落。字幕只过滤命中行会丢上下文，因此详情默认定位并高亮，前后文仍然可读。

返回恢复按搜索上下文隔离：URL 保存查询／范围／筛选／排序；session 状态保存已加载页、锚点、滚动、焦点。搜索 → 笔记 → UP → 返回笔记 → 返回搜索，必须按原路恢复。直接打开详情没有来源时显示「返回资料库」。浏览器前进／后退与页面返回行为一致。

### 新建与任务

新建页保留链接输入、格式提示和「生成笔记」。桌面按钮随内容定宽；手机放在输入下方并右对齐，触达至少 44px，不把宽屏按钮拉满。已有笔记命中时主要操作是「阅读已有笔记」，重新生成作为次要操作并说明影响。

任务页用可扫读阶段：获取信息 → 获取字幕或转写 → 生成笔记 → 完成。不展示无数据依据的百分比或 ETA。不需要用户留守，提供「回资料库」。完成后突出「阅读笔记」，不突然抢走用户正在阅读的区域。失败显示具体阶段、可理解原因和对应恢复动作；错误详情可展开复制。邮件失败与笔记生成成功分开表达。

### 移动端

内容边距 16–20px；正文 16px、约 1.75 行高；标题不挤在两侧图标之间。搜索、范围、筛选分行；列表标题允许两行，弱化日期与时长。主要触达区域不低于 44×44px。移动端底栏预留 safe-area，内容留足底部间距，弹出键盘时不得遮住输入、提交和结果。

详情直接全屏阅读，不先弹抽屉再进详情。目录使用可展开区域；正文和字幕以页面滚动为主，避免手机屏幕内又嵌一个 60vh 滚动框。窄屏靠换行和布局切换适配，不靠 overflow-x:hidden 隐藏溢出。

## 文案与组件约束

| 现有表达 | 建议表达 | 适用情境 |
| --- | --- | --- |
| 历史 | 资料库 | 已保存内容；运行和失败记录进入任务 |
| 搜索笔记 | 搜索资料库 | 统一搜索；不再作为独立导航 |
| 开始总结 | 生成笔记 | 提交视频链接 |
| 再贴一条 / 新建 / 粘贴新链接 | 新建笔记 | 同一目的地统一称呼 |
| 重新总结 | 重新生成笔记 | 内容菜单，说明会复用字幕 |
| 展开全文 | 展开此片段 | 实际只有 chunk 时避免承诺整篇全文 |
| 返回 | 返回搜索结果 / 返回资料库 | 明确目标 |
| 打开视频 | 在 B 站播放 · 08:24 | 外部动作与时间 |
| 清理历史 | 管理任务记录 | 不与删除资料库内容混淆 |

同组导航等宽；一般文字按钮按内容定宽，统一高度、内边距和圆角，不为追求所有按钮同宽制造空白。每个区域最多一个视觉主操作。按钮与普通文字的语义明确，图标不是唯一标签。hover 只作补充，键盘 focus 可见；高频搜索结果不做入场飞入动画，支持 reduced-motion。

## 后端能力边界与分期

当前 `/v1/jobs` 面向任务元信息；`/v1/knowledge/search` 面向正文证据。后者采用摘要发现、局部字幕及条件性全局补充，总量内部最多 12（retrieve.py:330–370）。这可以支撑精选片段展示，不能直接支撑穷尽的全部／字幕搜索和完整分页。

当前知识库已有 document 生命周期和 revision/artifact 基础，但 GET document 仅返回元信息（routes/knowledge.py:116–137），不能据此声称已有全文阅读 API。历史删除明确保留知识内容（HistoryPage.tsx:538）。因此内容页必须独立于 task 存活，权限检查仍沿用现有服务约束，不把 artifacts 文件系统路径暴露给前端。

1. **入口与阅读闭环**：统一壳、命名、尺寸及 URL 状态；增加稳定 document 阅读接口和定位。短期兼容已有 jobs 链接，未入库完成任务要有可见的同步状态／受控回退，不能迁移后消失。允许先保留旧精选检索，但必须标明展示边界，不上线假的全面搜索选项。
2. **完整统一检索**：服务端按文档聚合元信息、笔记和字幕；范围独立执行；用 provider+BVID+CID 或 document ID 正确识别分 P，去重不只看 BVID；提供分页、稳定排序、来源命中、局部失败与索引状态。采用文档级分页，组内命中另取，不让一个长视频占尽第一页。
3. **长尾体验**：本篇查找、UP 已保存／在线投稿切换、任务筛选、键盘与移动端细节；补真实数据的检索质量评估。暂不加入聊天问答、语义检索或自动推荐，先把确定性查找做完整。

现有 `/v1/jobs?query=` 的筛选还被批量删除复用（jobs/repo.py:817），统一入口应新增只读聚合契约，不能扩大旧 query 的含义。任务命中可用单独的辅助分区或任务入口呈现，不与文档混排、不合计跨区总数。现有 FTS 异常还有被转成空数组的路径（knowledge/search.py:115、knowledge/retrieve.py:158），正式改造需显式传递失败状态。

删除任务记录与移除资料库内容是两个独立动作。此次设计不授权改变删除语义或执行数据迁移。未索引、未开启字幕索引、部分搜索失败都要明确呈现：不能把服务不可用显示为「没有结果」。

## 验收标准（正式实现阶段）

- 标题、UP、BV、标签、只在笔记中出现的词、只在字幕中出现的词，都能从统一入口找到；中文、英文、多词、标点与当前 FTS 规则一致。
- 相同视频多个任务正确合并；不同 CID 不误合并；历史任务删除后，保留的 document 仍可阅读。
- 搜索 → 笔记／字幕 → UP → 返回，查询、范围、筛选、排序、已加载结果、滚动与焦点保留；直接 URL 与浏览器前进后退都可用。
- 连续提交不同查询、慢请求后返回、请求取消，旧结果不会覆盖新查询；禁用索引与网络失败不是空结果。
- 命中内容的版本、章节和字幕时间正确；过期定位有明确回退；站外跳转时间准确。
- 320、390、768、1440 宽度不横向溢出；键盘可完成搜索、筛选、打开与返回；实机检查软键盘和安全区。
- 一组真实样本对比重构前后：找视频、找某个观点、追溯原字幕所需步骤和时间，以及首屏有效命中。未采集前不承诺性能提升数字。


## 调研分工

独立完成了搜索契约与信息架构调研、页面与移动端源码审查，主模型综合决策并实看本地界面。对于建议分歧，本提案选择独立任务入口、document 为主的阅读页；不采用只增加 job_id 后回跳任务页的临时方案作为最终架构。

## 原型查看

打开同目录 `index.html` 为多页面评审台，可切换桌面、390px 手机与 320px 窄屏；`prototype.html` 为独立可交互原型。场景包括资料库、搜索、笔记、字幕、新建、任务、UP 已保存内容、空态和失败态。桌面与手机共享语义和状态，使用不同布局。

推荐评审路径：资料库搜索「注意力」→ 查看命中笔记 → 切换字幕 → 返回搜索；另试无匹配关键词、不同范围、UP 链接、新建示例和失败重试。评审台切换场景可直接跳转；更完整的来源上下文请通过原型内部链接体验。

原型展示拟议交互，静态样例不代表现有后端已支持聚合、全文读取或分页。在线 UP 投稿、真实视频外跳和真实生成不会在此原型中执行。名称与色彩均可独立调整。

## 本轮实际验证

- `node --check`：提取 `index.html`、`prototype.html` 的脚本执行，均通过。
- Playwright CLI：9 个场景 × 1440 / 768 / 390 / 320px，检查 `document.documentElement.scrollWidth <= innerWidth`，36 项均通过。导出 9 组桌面／手机截图，见 `screens.html` 与 `screenshots/`。
- 浏览器交互检查：笔记／字幕范围过滤、正确文档和 UP 内容、字幕高亮、目录不误触发路由、详情 → UP → 详情 → 搜索返回，均通过。
- 浏览器交互检查：空链接不提交、填入示例后进入任务、失败后重试回生成态、空结果清除、首次查询默认相关性，均通过。自动化第一次跨页面操作遇到旧 DOM 引用，重新等待目标页面后继续验证通过。
- 手机返回滚动实测：打开第二个结果前 `scrollY=771.5`，返回后 `scrollY=771.5`。原型仅演示当前会话内恢复；正式实现仍需按提案补 session 持久化和分页恢复。
