# 多来源笔记与远程 Mac mini

笔哩支持 B 站单视频、YouTube 单视频，以及从浏览器上传音视频或 UTF-8 SRT/VTT 字幕。所有来源进入同一任务、转写、总结和资料库流程。MediaGo 不属于运行依赖；可以先用它获取媒体，再通过首页「导入文件」上传。

## 使用方式

首页输入框识别 B 站与 YouTube 链接，普通文字仍搜索笔记。来源检查由服务端返回已有笔记、最近删除内容或执行中任务。B 站按 BV + CID 区分分 P，YouTube 按视频 ID 区分内容；主动「重新生成」绕过去重。

「导入文件」展开内联面板，允许填写标题和可选来源页面。来源页面仅作为回看链接保存，不会由服务器抓取。文件通过现有 API 发送到 Mac mini，不能填写用户电脑的本地路径。SRT/VTT 直接进入总结，音视频先检查音轨与时长，再生成供 ASR 使用的音频。

上传和服务器检查完成、返回任务 ID 后，才可以离开页面。首版是限额流式上传，不支持断点续传。网络中断时重新选择文件提交；已接收的同一文件会按 SHA-256 复用可用任务。取消请求与服务器接收可能竞态，若在检查阶段取消，可到任务页确认是否已接收。

YouTube 先选择可用人工字幕，再选择自动字幕；没有字幕时下载音频进行 ASR。首版不接受播放列表、直播或需要在界面传递 Cookie 的内容。平台访问、地域与登录限制仍可能导致获取失败。

## 服务端配置

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `JOB_URL_ALLOWED_HOSTS` | `bilibili.com,b23.tv,youtube.com,youtu.be` | 入口域名限制；适配器仍只接受支持的单视频路径 |
| `UPLOAD_STORAGE_DIR` | `data/imports` | 后端管理的原始导入文件目录 |
| `UPLOAD_MAX_BYTES` | `83886080` | 每个请求最多 80 MiB，按实际收到的字节检查 |
| `UPLOAD_STORAGE_MAX_BYTES` | `2147483648` | 导入目录的容量预算，接收前预留一个最大文件的空间 |
| `UPLOAD_MIN_FREE_BYTES` | `1073741824` | 接收前保留的磁盘空闲余量 |
| `MAX_VIDEO_DURATION_SECONDS` | `14400` | 媒体与字幕最大时长，4 小时 |

同一服务进程同时接收一个导入请求；请求还受现有鉴权、频率限制和任务容量限制。文件扩展名之外，ffprobe/ffmpeg 也会限制媒体格式与协议。能力接口只检查工具路径和 ASR 包是否安装，不代表模型已加载或某网站一定可访问。

原始上传文件独立于笔记存储。结束的任务保留原始输入 7 天，之后清理输入但保留转写和总结；活跃任务的输入不会自动删除。原文件被清理后仍可重新总结，重新转写需要重新导入。手动删除任务会清理其输入。永久删除资料库笔记也会清理关联任务在服务器保存的导入原文件；任务记录会保留，B 站和 YouTube 等外部平台的原视频不受影响。未关联任务的文件经过孤儿文件宽限期清理。YouTube 下载崩溃留下的专用临时目录，在超过一小时且不属于当前活跃下载时，由启动及定期维护清理；不跟随符号链接。

现有知识库备份覆盖数据库及长期笔记产物，不包含临时导入原文件；若需要恢复尚未转写的任务，应在停止服务后额外保存 `UPLOAD_STORAGE_DIR`。不要将知识库备份视为原始媒体归档。

## Mac mini 升级与验收

本地测试不证明远程机器可获取 YouTube，也不证明 Mac mini 的 ASR、模型缓存或代理可用。以下操作应在确认目标版本和部署授权后执行。

1. 确认 Mac mini 的代码版本、启动用户、Python 环境、数据目录与前端 API 地址。保留现有宿主机 Python/MLX + LaunchAgent 方式，无需安装 MediaGo。
2. 停止服务后做一致备份：保存数据库、长期产物、当前配置和需要恢复的导入文件。保留升级前代码版本。
3. 在备份副本上启动新版本并检查迁移。迁移保留已有文档 ID、版本、任务关联及删除标记，为文档增加通用来源键。不要直接用生产数据库做本地试验。
4. 旧 `.env` 若显式限制为 B 站域名，需要有意追加 `youtube.com,youtu.be`。修改示例或代码默认值不会覆盖已有 `.env`。
5. 在 LaunchAgent 的实际环境确认 ffmpeg、ffprobe、yt-dlp 和所选 ASR 可用。确认 HTTPS/反向代理/隧道允许的请求大小与超时；链路限制可能小于应用的 80 MiB。
6. 上传入口应位于已有可信访问边界内。前端构建时嵌入的 API Token 不是私密凭据；公开部署需要私网或访问控制层，不能仅靠该 Token 保护上传和处理资源。
7. 先启后端，确认 `/healthz` 与鉴权后的 `/v1/sources/capabilities`，再更新前端。
8. 验证 B 站有字幕、不同分 P、YouTube 有字幕与无字幕、SRT 导入、小型音频导入、重复提交、读取与搜索。检查实际任务、产物和日志，不只检查 HTTP 状态。
9. 在测试任务上验证取消、进程重启、转写失败后的重试、原文件清理和重新总结。完成后再提高上传限额。

回退时先停止服务，恢复升级前代码与一致的数据备份。不要直接让旧代码写入已迁移的新数据库。

## 实现边界

`sources/model.py` 提供通用元数据；B 站保留兼容导出，其他模块不必依赖 B 站模型。`sources/service.py` 解析受限来源，`sources/youtube.py` 与 `sources/uploads.py` 获取字幕和音频；`jobs/runner.py` 继续管理状态和并发。持久内容身份为 `(provider, source_id, source_part)`，上传请求不接受任意服务器文件路径。

设计参考 MediaGo 的来源适配、下载产物验证和发现/执行分离。没有嵌入 MediaGo 的 Go 服务、Electron 或第三方下载工具集合。浏览器嗅探、MediaGo API 自动联动和课程批量处理不在此版本中。
