# 2026-07-28 历史归档、真实费用与周总结

## 背景与决策

历史记录目前是长列表：初始拉取、后台分页与前端滚动展示彼此独立，筛选在前端完成；已有的“清空已完成”并不跟随筛选，而是由服务端对全库执行宽范围删除。统计页把完成量、视频时长、标签、热力图、tokens、估算人民币费用和余额分散到多个卡片，造成空间浪费，且固定单价估算不能代表真实扣费。

本计划落实以下已经确认的产品方向：

- 历史页按周归档；最新周默认展开，其余周独立展开；周内保留静态日期标题。
- 标题搜索、UP 主和标签筛选共同决定批量删除范围；删除作用于数据库中的全部匹配项，而不是已滚动加载或当前屏幕可见项。
- 统计页只聚焦 API 余额、已确认真实费用、tokens、12 周费用趋势和周总结。
- 周总结按需生成、持久化，并可稳定引用到具体总结；删除原总结后，受影响的周总结必须失效。

## 目标

1. 历史页在不牺牲按日期定位能力的前提下，显著缩短首次页面长度。
2. 提供标题、UP 主、标签的可搜索筛选；桌面端同行展示，移动端收进筛选面板。
3. 将批量删除改成“删除当前筛选结果”，并在确认前准确说明数据库内将删除的数量、状态、样例、关联文件及受影响周总结。
4. 为每次 LLM 请求持久化可追溯的真实费用事件；只有供应商确认的实际金额才计入费用统计。
5. 用成本监控卡替代现有冗余统计区块，并加入可跳转引用的按周总结。

## 非目标

- 不以 token × 当前价目表的方式回填或估算历史真实费用。
- 不把余额变化推断为费用，不计算未经真实账单支持的“可用天数”。
- 不做严格单开手风琴、时间轴、无限虚拟列表或多选复杂筛选器。
- 不引入自动定时生成周总结，避免用户未访问时产生 LLM 消耗。
- 不处理部署、充值、汇率换算、外部账单平台的账户配置；不提交或推送 Git。

## 现状证据

- `web/src/pages/HistoryPage.tsx`：历史数据分页/滚动展示与前端标题、作者、标签筛选均在页面中处理；清理动作未携带筛选条件。
- `web/src/lib/api.ts`：现有清理 API 没有查询作用域，无法表达“仅删除当前筛选结果”。
- `server/biri_youyaku/jobs/model.py`：现有“可清理”状态集合覆盖范围宽于按钮文字“已完成”，需要收紧成完成、失败、已取消，排除进行中、等待继续与蒸馏辅助任务。
- `server/biri_youyaku/jobs/repo.py` 与 `web/src/lib/stats.ts`：历史排序和统计归周使用的时间字段不一致，统计还使用固定费率把 tokens 换算为人民币。
- `web/src/pages/StatsPage.tsx`：余额、多个指标卡、热力图、周对比和 12 周图重复占用页面高度。
- `server/biri_youyaku/modules/storage/summary.py`：单条总结正文在独立 Markdown 中，周总结不能依赖历史列表每次临时读取全部正文，必须有独立缓存/持久化记录。
- `web/src/App.tsx`：已有任务详情路由可作为周总结引用的跳转目标。

## 关键口径

### 周归属

- “统计、周总结、已完成历史”统一使用用户本地时区、周一 00:00 为周起点。
- 已结束任务以 `completed_at` 归周；缺失该字段的旧数据回退 `created_at`，不得因后续编辑改变历史归属。
- 进行中的任务单独显示在历史页顶部，不进入周归档。

### 筛选与删除

- 有效删除条件为：标题/全文索引查询 AND UP 主 AND 标签 AND 状态属于 `COMPLETED`、`FAILED`、`CANCELED` AND 非蒸馏辅助任务。
- 所有筛选均为可选项；缺失筛选时对应条件不参与查询。
- 预览和执行均在服务端从完整数据库查询；前端已加载数量、展开状态、滚动位置不能影响结果。
- 弹窗打开后候选集变化时，执行必须拒绝且要求重新预览，不能静默扩大/缩小删除范围。

### 真实费用

- “已确认费用”仅来自供应商响应中的实际扣费字段、可按请求 ID 查询的账单事件，或官方账单/usage 导入的实际金额。
- 无法取得实际金额时保留 tokens 并标为待确认/不可用；绝不以余额差、固定费率或当前价格表补值。
- 金额以整数最小货币单位（或 micros）持久化；不同币种分组展示，未存汇率快照时不合并。
- 历史数据从真实费用追踪启用日起计算；无法可靠回填的旧记录明确显示“仅有 tokens 数据”。

## 数据表与 API 草案

### `llm_usage_events`

建议字段：

| 字段 | 说明 |
| --- | --- |
| `id` | 本地事件 ID |
| `occurred_at` | 请求/账单事件发生时间 |
| `job_id` | 可为空的关联任务 ID |
| `operation` | `summary_chunk`、`summary_merge`、`json_repair`、`tagging`、`distill`、`weekly_summary` 等 |
| `provider` / `key_fingerprint` | 供应商与不可逆 Key 指纹 |
| `requested_model` / `billed_model` | 请求模型与实际结算模型 |
| `input_tokens` / `output_tokens` / `cached_tokens` | 供应商返回的用量 |
| `provider_event_id` | 供应商请求/账单事件标识 |
| `amount_minor` / `currency` | 确认金额与币种，使用整数最小单位或 micros |
| `source` / `confirmation_status` | 响应、账单查询、账单导入及确认状态 |
| `created_at` | 本地写入时间 |

`provider + key_fingerprint + provider_event_id` 为唯一约束；导入来源若无法提供事件 ID，必须定义稳定且不会跨请求碰撞的幂等键。

### 周总结记录

建议单独表（例如 `weekly_summaries`），字段包括：`id`、`week_start`、`week_end`、`timezone`、`content`、`source_job_ids_hash`、`source_count`、`status`、`generated_at`、`model`、`usage_event_id`、`invalidated_at`、`created_at`、`updated_at`。来源任务 ID 另以关联表或可验证 JSON 存储，供失效和引用校验使用。

### 删除 API

```text
POST /v1/jobs/bulk-delete/preview
POST /v1/jobs/bulk-delete/execute
```

预览请求包含可选 `query`、`author`、`tag` 与固定终态范围；预览响应至少包含 `matched_count`、`by_status`、`sample`、`sample_truncated_count`、`affected_weekly_summaries`、`preview_token` 和 `expires_at`。

预览令牌绑定规范化筛选条件、候选任务 ID 集合哈希、状态分布、受影响周总结和过期时间。执行请求仅接受令牌；服务端重新查询并严格比对，失配返回 `409 Conflict`。

### 统计与周总结 API

- `GET /v1/stats/costs`：余额（如可用）、按币种的已确认本周/累计费用、费用覆盖率、tokens、12 周费用序列、按操作类型聚合与追踪起始时间。
- `GET /v1/weekly-summaries?week_start=...`：返回有效/失效/不存在状态和服务端组装后的安全引用。
- `POST /v1/weekly-summaries/{week_start}/generate`：按需生成或刷新；当前周语义为“截至目前”，无来源时不调用 LLM。

## 风险与缓解

- **删除不可逆且数据量大**：坚持 preview/execute 两阶段、数据库全量查询、候选集哈希与短时令牌；确认框明确文件与周总结影响。
- **文件删除和 DB 事务不天然原子**：先确认现有清理能力；记录可重试的待清理文件任务或采用可恢复顺序，禁止在 DB 删除成功后静默吞掉文件错误。
- **统计误导**：费用卡只以“已确认费用”命名，显示覆盖率和追踪起始时间；没有可靠金额不显示金额。
- **供应商差异与价格变化**：按供应商/币种保留原始确认金额，不以当前价格倒推；适配器逐一以真实响应或账单证据验收。
- **周总结幻觉/越权链接**：模型只能从服务端给出的任务白名单选择 ID，标题和 URL 均由服务端生成。
- **时区与周边界**：所有读写共享一个 helper，并为周一边界、夏令时/时区变化（如支持）和旧数据回退写测试。
- **性能与大历史库**：筛选、预览和周聚合必须分页/索引化；避免把全部 Markdown 正文加载到历史列表。
- **现有用户数据迁移**：新增列和表使用兼容迁移；历史费用不伪造回填，历史周总结按需开始生成。

## 验证与验收标准

### 自动化验证

- 服务端：筛选查询、周归属、删除预览/执行/409、状态与辅助任务排除、文件删除、周总结失效、费用事件精度与幂等、真实费用聚合、引用白名单均有测试。
- 前端：类型检查和生产构建通过；删除弹窗、筛选状态、周分组、缺少费用和失效周总结状态至少有组件或端到端覆盖。
- 全局：项目适用的 pytest、lint、格式/类型检查和 `git diff --check` 通过；若存在既有失败，单独记录其证据与本次无关性。

### 用户验收

- 历史页默认只展开最新周，其他周不会把页面铺成长列表；周内可按日期找到记录，展开多个周不会互相关闭。
- UP 主、标签下拉可搜索，和标题搜索共同生效；移动端筛选不挤压主搜索框。
- 删除筛选后的 UP 主/标签/标题结果时，弹窗的数量与数据库完整匹配集一致，明确说明不是仅删除已加载项；确认后只删除匹配终态，进行中、等待继续和辅助任务仍存在。
- 在预览弹窗打开后改变匹配集，确认操作被拒绝并要求重新预览，零条意外删除。
- 统计页首屏可看到余额、已确认费用、tokens、12 周真实费用趋势和本周总结；不再有固定费率的“实际花费”。
- 有实际费用来源时，本周/累计/操作类型合计和供应商事件一致；没有来源时页面清楚显示待确认而非估算。
- 周总结可以引用并打开对应任务详情；删除被引用任务后该周总结不再显示旧摘录，显示需要更新。

## 实施备注

已按计划实现，原始计划文字保留。主要实现如下：

- 服务端新增统一周边界、完整数据库筛选与作者/标签聚合查询；旧客户端仍可使用原有历史列表分页契约。已结束任务按 `completed_at` 归周，缺失时回退 `created_at`；进行中与等待继续不进入周归档。
- 新增 `llm_usage_events` 与 `weekly_summaries` SQLite 迁移、仓储和路由。费用事件以整数 micros 保存，包含请求/结算模型、Key 指纹、供应商事件 ID、tokens、确认状态和来源；旧任务不会按当前价格伪造回填，统计明确其只具有 tokens 数据。
- OpenRouter 响应中的 `usage.cost` 会被记录为已确认真实费用。普通 API Key 只展示可取得的 usage/余额范围；management key 可查询账户余额。DeepSeek 与其他供应商的官方账单/usage 导入仍未实现：当前没有可验证的真实账单样例，因而保持 fail-closed，不把余额差或价目表估算当作真实费用。
- 新增两阶段筛选批量删除：预览在完整数据库候选集上生成短期快照令牌，执行在事务内复核候选集哈希；令牌过期或集合变化返回冲突。成功后清理关联文件、失效关联周总结，并保留待清理记录以处理文件删除失败。
- 周总结按周持久化并用租约避免重复生成；来源集合变化会失效缓存。模型引用仅可使用服务端白名单中的任务 ID，服务端负责注入标题及站内详情链接。
- 历史页加入周独立展开、日期分隔、进行中区域、可搜索 UP 主/标签筛选和详细删除预览；统计页收敛为余额、已确认成本、tokens、12 周费用趋势和周总结。历史 API 的分页兼容旧调用，删除仍以数据库完整匹配集为准，而不是已滚动加载条目。

兼容与迁移：新表/列通过兼容 SQLite 初始化迁移创建；历史记录继续可读，历史 tokens 不等于历史账户总消耗。费用覆盖率只对已记录的请求统计，未获取确认金额的请求保持待确认或不可用。

验证结果：服务端 `pytest` 236 项通过；`ruff` lint 通过；Web 生产构建通过；`git diff --check` 通过。仓库原有格式基线存在与本次变更无关的问题，未借本次任务进行全量格式化。

以下验收尚未完成，故保持未勾选：DeepSeek/其他供应商官方账单导入需要真实供应商账单样例；桌面端与移动端浏览器视觉、真实账户余额/费用数据验收由用户执行。

## 审查 / 问题与根因

独立审查已完成；以下问题均已修复：

- **筛选快照与事务边界**：初版风险是预览与执行之间候选集变化会扩大删除范围。根因是前端滚动加载数据并非数据库全集。现以服务端规范化筛选、候选 ID 集合哈希、短期令牌和执行时复核解决，失配返回 `409`，事务内不删除任何记录。
- **周总结租约与 TOCTOU**：并发打开同一周可能重复触发 LLM 生成，来源变化也可能在生成完成前发生。根因是缓存状态与生成请求没有互斥关系。现以生成租约和来源哈希复核控制；来源变化时保留失效状态，不发布过期生成结果。
- **usage 覆盖率与历史数据**：将“有 tokens”误报成“已确认花费”会误导成本统计。根因是旧任务没有供应商确认金额或请求事件。现将确认费用、待确认请求和 legacy tokens 分开聚合及展示，历史边界明确标注。
- **分页兼容**：把筛选全面迁到服务端时会破坏旧前端的分页响应。根因是新查询参数与旧分页契约耦合。现保留原参数与响应形状，新增筛选为可选字段。
- **Markdown 外链**：模型自由生成 Markdown 链接可能指向外站或伪造任务。根因是把模型文本当作可信展示内容。现只接受白名单任务 ID，服务器组装标题和站内 `/jobs/:jobId` 链接。
- **单删、批删竞态**：单条删除与批量执行可同时触及同一任务和引用周总结。根因是不同删除路径没有共享失效与待清理语义。现两条路径复用事务内周总结失效和 pending 文件清理流程，重复删除安全返回且不会恢复失效总结。

遗留风险：没有真实官方账单样例前，DeepSeek 与其他未覆盖供应商继续不显示“已确认费用”；视觉和真实账户数据仍需用户在桌面端、移动端与其实际 Key 下验收。
